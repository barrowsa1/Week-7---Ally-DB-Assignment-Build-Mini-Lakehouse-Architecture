# README For Assignment 7
For this project, I created a mini lakehouse to organize and analyze student engagement data from September, October, and November 2024. I stored the data in CSV files and organized them into folders based on the year and month. This setup makes it easier to organize the data and find specific months when analyzing student engagement. The dataset contains 30 student engagement events, with 10 events in each monthly partition. The data includes information such as event ID, student ID, event type, event date, duration, and campus. I also included metadata files to describe the data structure and explain how the schema can change over time.The project includes several files and folders that work together to store and analyze the data. The lakehouse/engagement folder contains the monthly CSV files, while the lakehouse/metadata folder contains the metadata files and schema_evolution.md. The metadata files describe the table columns, data types, required fields, and partition keys. The first schema version contains six columns, and the second version adds an optional advisor_note column. This demonstrates schema evolution because new information can be added without requiring all the older CSV files to be changed. If an older file does not contain an advisor note, its value can be treated as NULL. The duckdb_queries/queries.sql file contains five queries for analyzing the student engagement data, and lakehouse_reflection.md explains what I learned from building the mini lakehouse.

To run the project, open a terminal in the project folder and start DuckDB by entering duckdb. Next, open duckdb_queries/queries.sql in VS Code and run the SQL statements in the DuckDB terminal. The queries read the CSV files directly from the lakehouse folders, so the data does not need to be loaded into a separate database table first. I created five queries to display engagement events from September, calculate the average duration for each event type, filter workshop events at the St. Paul campus, count events at each campus, and demonstrate how an optional advisor_note column can be included in a query. Working on these queries helped me practice using SQL to read, filter, group, and analyze data stored in partitioned files.
