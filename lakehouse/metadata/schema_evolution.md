# My Schema Evolution Explanation
Version 1 of my student engagement table has six columns, which are event_id, student_id, event_type, event_date, duration_minutes, and campus. In version 2, I added an optional advisor_note column so that advisor notes can be included when needed. The older CSV files do not need to be changed just because a new column was added. The newer files can include the advisor_note column, while the older files can stay the same. If an older file does not have an advisor_note, that value can be treated as NULL. This allows both versions of the data to still be used without having to update every file. Keeping track of schema versions helps keep the data organized as new information is added. It also makes it easier to update the dataset in the future without having to start over or change all the existing files.
